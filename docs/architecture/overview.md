# 架构与边界

## 服务职责

`qqbot.app` 组合依赖、维护串行前台队列及生命周期。每轮消息状态属于 `Turn`，后台偏好与记忆任务不修改发送状态。会话编排、模型传输、OneBot、存档、面板、空间任务与图记忆分别位于责任模块；纯记忆策略不依赖 torch 或 Neo4j。

`qqbot.conversation` 负责有界工具循环与最多一次的文字修订；`model` 统一 SSE/JSON 解码、传输恢复、协议修复及可见输出边界。`transport.onebot` 是唯一文字/图片发送路径。工具返回仅为不可信资料，工具清单不按请求修改共享注册表。

`qqmemory` 提供鉴权 API、证据关联、图存储、时序修订和召回。Qwen3 Embedding 与冻结 R-GCN 使用本地只读模型；合成训练工具离线运行。显式召回反馈只调整有限排序注意力。

## 消息顺序

1. OneBot 事件经过账号、场景、消息类型、引用、时效、去重与冷却校验后排队。
2. 创建单轮状态，先处理本地命令，再恢复当前账号与场景最近成功发送的短历史。
3. 引用作为带传输校验角色的不可信数据。记忆按账号、受众、场景与 generation 召回，并在模型输入前再次过滤。
4. 面板请求隔离长期记忆；UID 只从真实会话用户输入授权。模型工具循环至多两轮执行、四次尝试，第三轮只接受最终回答。
5. 完整响应通过内部记忆容器、推理、工具协议及人物归属检查。残缺协议至多修复一次，重复泄漏阻断发送。普通代码、JSON及明确索要的协议示例保留。
6. 文字和校验图片通过一个 OneBot 动作发送。成功后提交短历史、标记存档 delivered，再安排偏好更新和记忆 intake。失败只留下审计记录。

## 身份与撤销

actor 使用稳定盐对 QQ user ID 做 HMAC；scope 同时绑定账号与群/私聊场景。同名、相似口吻、自称换号和助手旧话均不能认证身份。称呼与表达偏好按适用性延续，其他资料依受众和场景过滤。

删除或暂停先持久写入新 generation 与控制任务；待同步的撤销立即阻断召回及 intake。服务在慢模型调用前后持有或重新检查 actor lock、generation 和撤销状态。重试与旧任务不能恢复已删除资料；状态冲突需要人工核对，不假装成功。

## 空间与面板

空间发布只接受已配置管理员的明确私聊指令，使用独立队列、日志及模型状态。公开评论仅接收当前已核验分支，不读取个人记忆。暂停与撤销使未开始的写入失效；结果未知不自动重发。

面板服务没有 QQ 凭据或聊天存档，只调用允许的公开展柜操作。图片通过类型、大小与校验值验证，只交给当前发送动作。只读查询服务也没有 QQ 密钥、模型密钥或聊天卷。

## 故障处理

记忆不可用时普通聊天可继续，但待撤销账号保持关闭召回；outbox 有容量与重试上限。面板失败只影响对应查询。前台保持单消费者；增加并发前必须隔离每轮状态与缓存。日志仅含状态、异常类别、耗时和数量。
